## 获授权后执行的工程步骤

1. 记录UTC及北京时间、源实例非敏感标识、Postgres版本、实际迁移账本/校验值和私下账号基线；不记录密码。对账本、账号哈希/分配、消息/状态/评分做只读快照摘要。若实验仍写入，用一致性快照而不是跨时点随意比较表计数；先协调无写入验收窗口，不能擅自Suspend/Restart。备份期间新消息需记录快照边界，不能称为丢失。
2. 使用Postgres18 `pg_dump` custom格式完整导出**单个已核实研究数据库**，不只导出research schema：包含research_meta.schema_migration、全部research表、索引/约束/序列/函数/触发器。实际表至少有participant/password_hash、experiment_assignment、auth_session、experiment_session/state、conversation/turn/message、state_transition、experiment_variable、model_run_log、admin_event、submission_receipt，以及配置experiment/template/agent/version/condition/prompt；如果004存在还包括chat_notice。不改源库、不运行迁移。
3. 凭据通过受控的Postgres service/密码文件或同等Secret机制注入，权限0600，不出现在命令行、shell历史、日志、聊天或Git。校验TLS主机证书；不要禁用TLS验证。dump可用 `--no-owner --no-acl` 便于隔离恢复，但角色/权限需另存受控清单并核实恢复映射，不能声称已完整恢复原角色权限。
4. 限制临时文件权限，在私有磁盘生成dump；使用既有AES256GCM备份封装（scripts/encrypted-backup.mjs，经18流程审核后使用）加密；密钥/密钥版本与密文分开保管。记录密文SHA256、字节数、工具版本、源实例标识、快照时间和私有位置。真实dump/密文/密钥不进GitHub或ZIP。只向研究者提供不含数据的收据，确认加密文件可读取后依保留策略处置明文。
5. 从拟用于恢复的那份私有密文读取并核对SHA256，验证解密/认证标签；`pg_restore --list`先检视清单。恢复前核实独立目标为空且绝非原staging，要求显式目标确认；不使用 `--clean` 对现有库覆盖。恢复到隔离Postgres18，遇错终止。
6. **先不启动Hosted应用**（启动会自动迁移和bootstrap）。对照备份时快照，核对全部schema/table/count、外键/唯一性/不可变约束、序列、迁移账本、分配及消息/评分/变量关联、完整导出摘要；核实不存在缺表、孤立行、账号串组、消息丢失。应用级登录验证在另一个授权隔离副本中运行匹配迁移版本的兼容代码；真实模型关闭/测试替身，仅用既有测试账号私下验证登录及历史/评分，不向参与者公开恢复库。不能在baseline核对前让新应用先应用004改变目标。
7. 若有已批准的异地存储，再实际取回同份密文到另一隔离目标重复恢复；只在真正完成后记异地PASS。记录恢复耗时、目标、表计数/约束、账号登录/分组/历史/评分结果、错误及修复；现在全为NOT VERIFIED。
8. 只有源库关联、完整备份、隔离恢复、004迁移兼容性和旧账号基线均有证据后，才请求一次明确部署批准。004有记录后down被拒绝，旧ea9867d不认识004，不能盲回滚；保留源数据，优先兼容前向修复。
