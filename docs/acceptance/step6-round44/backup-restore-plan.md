## 完整备份流程：获批后的工程操作

1. **私下确认源与目标。** 在受控环境核实Web实际DATABASE_URL目标与源实例关联，不把连接值发到聊天；只输出脱敏源标识、数据库名、Postgres版本。将源与恢复目标实例/主机/端口/库名逐项比对，目标必须独立且为空。不要修改Web的DATABASE_URL或任何API Key。
2. **PG18预检。** pg_dump、pg_restore与隔离目标均用18主版本，确认工具版本、磁盘容量、TLS证书验证及已有账号SELECT权限。现有PG17 production-backup-job.mjs固定专用production库/scope，不得套用到本库或修改scope绕过。若权限不足，停止，不自行授予角色或修改源库。
3. **私有凭据。** 由研究者本人在本机设置0600权限的Postgres service/密码文件，或同等受控Secret；命令只引用service别名，不带URL/密码，不入shell历史、普通日志或Git。使用sslmode=verify-full及可信证书，不禁用校验。不要发送密码给Codex聊天。
4. **一致性快照与基线。** 为避免边导出边写入造成计数不一致，可用一个短时、只读REPEATABLE READ事务导出pg_export_snapshot；在同一快照下采集所有表计数、按主键排序的分块摘要、迁移账本/约束/序列与账号/分配/历史/评分关联基线，pg_dump引用该snapshot。保持事务至dump完成；设置有限时长并监控，长事务可能增加旧版本保留、I/O/存储压力，不能称为零影响或无限保持。正常写入无需被停止；快照之后新增数据属于下一份备份，不是假称丢失。遇超时或压力停止并释放事务，不Suspend/Restart源库。
5. **单库完整dump。** 使用custom格式，不只筛research schema，也不只导出分析CSV。包括research_meta.schema_migration，以及所有业务表、索引、序列、函数、触发器、外键/唯一性约束；实际账本若仅001–003，不能先应用004来让备份符合新代码。若004已存在，也备份chat_notice。
6. **覆盖范围。** participant含password_hash；experiment_assignment；experiment_session/state；conversation/turn/message；state_transition；experiment_variable；model_run_log；admin_event；auth_session/token_hash；submission_receipt；experiment、template_version、condition/condition_prompt、agent/agent_version、prompt_version、state_machine_version；以及实际库里的其他表。只保存密码哈希，不尝试恢复旧明文密码。
7. **角色/权限边界。** dump可采用no-owner/no-acl便于隔离恢复，但另行在私有清单保存原owner、ACL、扩展、默认权限与恢复映射；业务登录表完整不等于Postgres全实例角色/权限已恢复。不能要求托管库超级用户权限或导出其他租户的全局角色。
8. **加密、校验、私存。** 临时目录0700、dump0600，使用已存在AES256GCM封装scripts/encrypted-backup.mjs加密，保留认证标签。独立保管32字节密钥与版本；密文存于批准的私有磁盘/存储，研究数据、密钥、连接配置不进项目ZIP或GitHub。记录备份UTC/北京时间、源实例非敏感标识、快照边界、PG版本、密文字节数/SHA256、私有位置、权限清单位置。校验并按批准策略处理明文，不承诺SSD删除等于不可恢复擦除。
9. **关闭访问窗口。** dump完成释放快照事务与连接；由研究者撤销本次临时IP规则，确认原有规则保持，保留脱敏审计收据。不要为了恢复验证而让源库继续暴露。

### 命令骨架（仅说明；当前不执行）

确定受控电脑和操作系统后，再生成可执行的一组命令。以下service别名必须事先私下配置，不能把真实Secret替换进报告。

```sh
pg_dump --version
pg_restore --version
# 快照持有连接仍处于只读事务中时，使用其导出的快照标识：
pg_dump --dbname=service=research_source44 --format=custom \
  --no-owner --no-acl --snapshot="$RESEARCH_BACKUP_SNAPSHOT" \
  --file="$RESEARCH_PRIVATE_DIR/source.dump"
# 加密后，从批准的密文位置取回、校验并解密至新的私有文件；密钥不通过命令行传入。
pg_restore --list "$RESEARCH_PRIVATE_DIR/restored.dump"
# 仅在独立目标身份、空库和授权均已核实后；绝不对原staging执行：
pg_restore --dbname=service=research_restore44 --no-owner --no-acl \
  --exit-on-error --single-transaction "$RESEARCH_PRIVATE_DIR/restored.dump"
```

快照标识/目录变量不得空值；服务文件必须显式指定正确dbname。上述命令骨架未包含目标防误操作的自动检查，**不能直接复制当作已批准完整脚本运行**。完整执行前还需源/目标身份核对和私有快照基线采集步骤。

## 独立隔离恢复验收

1. 在研究者明确批准的本地/既有受控环境中，使用独立Postgres18目标；限定loopback或可信私网，不暴露互联网。新目标实例或数据库尚未创建，不会自动创建。
2. 从最终私有存储取回密文，重算SHA256匹配收据，AES-GCM验签后才发布解密文件；wrong-key、篡改或目的文件已存在时应拒绝。pg_restore清单检视，不把清单/数据上传公开仓库。
3. 不使用--clean覆盖任何现有库，不连接源staging恢复；使用exit-on-error/单事务，任一错误立即停止。校验恢复schema、表/行数、同快照摘要、序列、触发器与约束、迁移id/checksum、账号哈希和分配/消息/状态/事件/评分关联。必要的owner/ACL映射与原差异单独记录，不伪称原权限全量恢复。
4. **先不启动Hosted应用。** 先验证原样数据，避免启动自动迁移/bootstrap改变恢复库。在第二个另行批准的隔离副本里，用与备份账本兼容的代码（源账本若仅001–003，可优先匹配ea9867d），关闭真实模型调用，用研究者既有测试账号实际登录、核对会话/分组/历史/评分及双账号隔离。认证验证只在恢复副本发生，不改源账号密码，也不把新auth_session误当原始快照一部分。
5. 演练结束形成私有恢复收据：源/目标、工具版本、密文SHA256、快照时间、逐表计数/摘要/约束、账本与旧账号登录/隔离、异常项、恢复时长。真实数据不入GitHub；公共报告只记录脱敏结论。若再要求异地恢复，必须从批准的另一地点实际取回同一密文并恢复后才能PASS，当前不是已验证异地备份。
6. 恢复演练成功后才讨论新代码004的增量迁移验证；不会对原库执行。备份批准不授权升级或部署，004有记录后旧应用/盲目down回退不安全。
