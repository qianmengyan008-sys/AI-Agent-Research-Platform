# 第40次反馈：日常路径与情感路径交互整改

来源：研究者在2026-10-21当前对话直接提交。按本轮最后要求，完成测试并报告后，由研究者决定是否部署Render。本文件不包含真实凭据。

请基于当前 GitHub 仓库、已有研究材料及 Render 线上版本直接修改代码并完成测试。不要重建项目，不要清空数据库，不要重置已生成的测试账号，也不要擅自修改研究设计。

本轮目标是让三条实验路径能够自然、稳定地完成实验，而不是单纯美化界面。

## 一、日常对话路径

### 1. AI 每轮只输出一个气泡，严格控制长度

当前日常路径的 AI 回复过长，像心理疏导而非日常聊天。

- 每轮 AI 只输出一个消息气泡。
- 每条 AI 消息不超过30个汉字，宜短不宜长。
- 使用自然、简洁、平等的伙伴式交流语气。
- 不要过度共情、总结用户情绪、反复肯定用户，也不要每轮都追问。
- 可以分享、回应、适当表达个人化的对话立场，并自然延续话题。
- 每轮最多提出一个问题，也允许部分轮次不提问。
- 用户发送的消息直接进入聊天记录，不要求额外确认。

30字限制适用于日常路径，不得直接套用到认知路径或情感路径。

### 2. 为四种实验条件设置固定的聊天对象

| 实验条件     | AI身份  |
| ------------ | ------- |
| 美国黑人男性 | Jamal   |
| 美国黑人女性 | Lakisha |
| 中国男性     | 王涛    |
| 中国女性     | 王静    |

请从WorkBuddy迁移材料、已有头像素材和当前代码中核对实际身份资料，并按既有研究材料呈现。

- 在聊天区域内显示当前AI的头像、姓名和身份信息。
- AI消息位于左侧，参与者消息位于右侧。
- 头像与身份应在每条AI消息附近保持一致。
- 不同实验条件使用对应的头像、姓名和身份，不得串组。
- 不要仅仅在页面顶部展示身份，而应让聊天对象在对话流中具有清晰、稳定的身份识别。
- 参与者不能通过修改请求参数自行切换实验条件。

### 3. 恢复日常路径开场白

请先检查WorkBuddy原始提示词、迁移包、MIGRATION_GUIDE.md及已有研究材料，找到并复用日常路径的真实开场白。

我要求尽可能与WorkBuddy保持一致，但目前不能仅凭已有截图确认原始开场白的逐字内容。因此：

- 如果找到原文，直接恢复原文，不要自行润色。
- 如果无法找到原文，请使用以下临时替代方案，并在交付报告中明确说明这是新拟定文本，而不是WorkBuddy原文：

“嗨！今天过得怎么样？最近有什么学习、生活或兴趣上的事想聊聊吗？”

开场白应由系统自动发送，不需要参与者先输入消息。

### 4. 测试账号必须固定绑定实验条件

管理员批量生成测试账号时，应能为每个账号分配并保存对应实验条件。

账号Excel至少包含：实验编号、参与者编号、登录账号、初始密码、实验路径、实验条件、AI姓名。

- 每个账号的实验条件在创建时确定，由服务端保存。
- 同一账号重新登录后，仍然使用原来的AI身份及实验条件。
- 不能在每次登录时重新随机分组。
- 不要覆盖现有账号，也不要因代码迭代重新生成全部编号。
- 密码按照现有安全设计处理，不得长期以明文形式存储在数据库中。

## 二、情感对话路径

### 1. 固定开场白和第二条引导消息

第一条AI消息必须逐字使用：

“嗨，很开心认识你！准备好跟我一起创作故事《打破心墙》了吗？讲述一个中国青年和美国留学生从彼此陌生到成为好友的过程。”

等待参与者回复后，再自动发送第二条引导消息：

“Marcus是一名刚来到中国留学的美国黑人青年。你可以补充他的外貌、兴趣和性格。”

之后按照既有情感路径实验设计继续推进故事，不得跳过原有阶段或自行改变剧情目标。

### 2. 取消情感路径中的“确认并继续”按钮

当前平台会把上一轮用户消息放进“确认并继续”卡片，导致用户必须点击确认才能继续交流。

- 参与者的普通文本消息直接发送给AI。
- 不再把普通用户消息自动填入确认卡片。
- 不再要求参与者点击“确认并继续”才能发送下一条消息。
- 取消情感路径中长期固定显示的确认输入框。
- 用户输入框只保留一个，位于聊天区域底部。

本项只针对情感路径。认知路径中研究设计明确要求的观点确认卡片、初次评分卡片和二次评分卡片必须保留，不得为统一界面而删除。

### 3. 每轮对话的气泡和长度限制

情感路径每轮AI回复：

- 最多3个气泡。
- 每个气泡少于30个汉字，宜短不宜长。
- 最后一个气泡负责提出一个明确的问题。
- 每轮最多提出一个问题，不得连续堆叠多个问题。
- 前面的气泡用于补充必要的故事内容、动作、心理活动或人物反应。
- 不要将一段完整剧情拆成大量零碎气泡，也不能为了满足字数限制而截断句子。

优先精炼文本，再根据完整语义拆分，不得直接截断模型输出。

### 4. 每个气泡必须明确说话人

- 涉及人物说话时明确标注是谁说的。
- 涉及人物动作或心理活动时明确标注对应人物。
- 例如：“Marcus说：‘这里的生活真新鲜。’”
- 参与者输入没有明确标注人物时可以结合上下文推断。
- 如果无法可靠判断，不要擅自编造人物归属，应通过一个简短问题澄清，例如“这是Marcus的想法吗？”
- 澄清问题也必须遵守每轮最多一个问题的限制。
- 不要为了标注人物而反复询问已经明确的信息。

### 5. 必须继续遵循既有情感实验设计

保留既有状态机、情感材料和剧情顺序，确保故事围绕中国青年与美国黑人留学生从陌生到成为好友的过程展开。气泡拆分、说话人标注和自然对话属于交互层修改，不应改变既有实验条件或核心研究材料。

## 三、所有路径共用的账号和历史记录要求

### 1. 同一账号持续保留两周的对话历史

参考DeepSeek长对话窗口：

- 重新登录后查看之前的完整聊天记录。
- 新消息追加原有历史，不覆盖旧消息。
- 刷新、关闭浏览器、服务重启和重新部署后从数据库恢复。
- 不设置一个会清空历史的“结束对话”按钮。
- 不混淆退出登录、结束当天使用和删除历史。
- 重新登录时恢复原会话，不重复初次开场白、不重置实验条件。
- 若研究设计要求每日分轮，在同一参与者历史下区分日期和轮次，不丢失此前记录。

### 2. 数据库和账号安全

保留现有测试编号、账号和历史，不在启动时初始化覆盖数据。修改数据库前检查备份与迁移方案；有风险时停止破坏性操作并说明。不伪造历史或虚构备份成功。验证账号、条件、消息与评分数据关联。

## 四、验收与交付

1. 日常每轮一个气泡、不超过30汉字。
2. 四种身份、头像、姓名、条件正确绑定，重新登录不变。
3. 日常正确自动开场，用户消息无额外确认。
4. 情感开场白、第二条指导语准确。
5. 情感普通消息直接发送，无确认卡阻塞。
6. 情感最多3气泡，每泡少于30汉字，最后气泡最多一问。
7. 人物说话、动作、心理明确归属，不明确时合理澄清。
8. 三条路径历史持久保存，重新登录继续原会话。
9. 认知原确认、评分、推进未破坏。
10. 旧账号及编号存在，数据库未清空或覆盖。

提供修改清单、测试结果、根因、提交版本及部署说明。失败项必须明确指出并给证据，不只报告“全部通过”。

普通消息顺畅发送 ＞ 回复长度、气泡及身份 ＞ 日常四组绑定 ＞ 情感研究设计 ＞ 两周历史和旧账号持久化 ＞ 界面。

不得重写研究材料、重建数据库或修改实验设计。完成代码修改后，先报告测试结果，再由研究者决定是否部署Render。
