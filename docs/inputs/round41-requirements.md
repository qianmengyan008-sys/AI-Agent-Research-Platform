二、本轮目标

建立可重复执行的迭代验收流程：每次修改都先完成代码审查和自动化回归，再进行针对性人工内部测试；只有通过安全检查并经研究者明确同意后，才更新 Render。每次交付必须明确列出研究者需要手动做什么、点击哪里、如何判断通过，以及失败时如何停止。

三、每轮必须执行的工程验收

基线与变更范围：记录基线提交、实现提交、修改文件、数据库迁移、环境变量变化。说明是否触及研究材料、状态机、Validator、账号/分组、数据库表。未授权时不得改动这些保护范围。

自动化检查：执行仓库规定的完整 npm run check，记录命令、退出码、Vitest 文件数/测试数、Playwright 浏览器测试数、构建和格式检查结果。不能只挑通过的测试，也不能放宽既有断言来换取通过。

路径回归：认知、情感、日常三条路径至少各执行一次自动化回归；变更路径需有专项测试。认知路径确认卡和评分卡必须本人提交；普通消息不能被确认卡阻塞；状态不能跳跃、重复或提前结束。

数据库和旧账号：涉及数据库、登录、历史、部署或迁移时，先证明迁移是增量兼容的；检查不会删除/覆盖旧账号、实验编号、分组、消息、评分和状态。没有可验证备份时不得执行破坏性操作。

真实模型证据：Mock 测试与真实模型测试分开报告。每次提示词、模型适配器、气泡/长度规则发生变化时，至少对受影响路径执行真实模型格式检查，并保存脱敏输入、原始响应、实际模型名、HTTP状态、耗时、重试次数和违规结果。不得把两次格式 smoke test描述为完整路径验收。

人工验收清单：每轮交付提供一份短清单，写清需研究者实际操作的页面、账号类型、测试步骤、预期结果、证据截图位置及停止条件。若本轮没有线上部署，必须明确标注人工线上测试尚未执行。

交付记录：更新 docs/inputs/round41-requirements.md、对应验收报告、机器可读 delivery-status.json 和变更清单；保留失败日志，不覆盖历史验收证据。

四、每轮人工内部测试：最小必测项

每次迭代均需要内部测试，但不必每次都重做整套生产验收。至少执行下列基线 smoke test；本轮改动涉及哪条路径，就对该路径追加完整的人工路径测试。测试只使用研究者创建的测试账号和合成内容，不使用正式被试数据。

测试项

研究者操作

通过标准

失败时处理

登录与开场

用现有测试账号登录；刷新并重新登录一次。

账号可用；实验路径和分组不变；旧会话不被重置；开场白不重复。

停止后续测试，记录账号类型和截图；不要新建/重置数据库。

日常路径

发3条短消息，观察AI身份与每轮回复。

每轮1个气泡、≤30个汉字；头像/姓名/身份固定；语气像普通伙伴，不长篇心理疏导。

保存问题消息、AI回复、账号实验条件和截图。

情感路径

按提示创作故事至少5轮，包含一次不明确的人物指代。

两条开场消息时序正确；普通消息直接发送；每轮≤3泡、每泡<30汉字；说话人清晰；不清楚时只问一个澄清问题。

不要点击不存在的确认按钮或重复发送；记录在哪一轮偏离。

认知路径

完成观点确认、初次评分，并推进至少一个重构阶段。

观点卡和评分卡仅在对应阶段出现；普通消息无需确认；评分由参与者本人提交；状态不跳跃。

不要用手工操作绕过卡片；保留状态截图和具体步骤。

管理员记录

用管理员权限查询刚才的测试会话。

AI/用户全文、时间戳、消息顺序、路径/分组及评分事件可查；普通参与者无法查看他人记录。

不把管理员密钥发到聊天或截图；报告缺失字段。

历史持久化

发送消息后刷新、退出登录再登录。

同一会话完整恢复，旧消息顺序不变，不重复创建开场白。

立即停止部署后继续写入；先确认是否数据库连接错误。
