# 第39次反馈：实验对话流程、聊天交互与数据持久化整改

来源：研究者于2026-10-21在当前对话直接提交。以下保存本轮要求；未收录任何真实账号、密码或管理员凭据。

请基于当前 GitHub 仓库和 Render 已部署的线上版本，直接检查、修改并测试以下问题。不要只提供修改方案，也不要重建项目或覆盖已有研究材料。

## 一、所有实验路径的共同要求

### 1. 恢复统一开场白

参考 WorkBuddy 实验平台，所有实验路径均使用以下共同开场白，作为 AI 进入聊天后的第一条消息：

“嗨，很高兴认识你！我平时很关注时事新闻，也特别想听听你的看法。你现在方便聊几句吗？”

开场白应由系统自动发送，不需要参与者先输入消息。

共同开场白之后，再根据参与者被分配的实验路径，发送对应的任务指导语。认知路径和情感路径必须使用各自已有的研究材料，不得混用提示词或自行改写研究内容。

### 2. 统一为微信式聊天界面

- AI 消息位于左侧，用户消息位于右侧。
- 底部仅保留一个统一的消息输入框，供用户自由输入并直接发送。
- 输入框应固定在聊天区域底部，不再同时出现两个供用户输入内容的窗口。
- 普通用户消息发送后，直接进入对话，不要求用户再次确认。
- AI 每轮回复最多拆分为 3 个气泡，按语义和完整句子拆分，不得按固定字符数机械截断。
- 同一轮 AI 的多个气泡应连续显示，不能被错误识别为多轮对话。
- 保留现有自动滚动、历史消息查看和刷新恢复功能。

### 3. 修复 AI 回复截断问题

目前部分 AI 回复会在句子尚未结束时被截断，影响实验体验及研究材料的完整性。

请检查后端模型输出长度限制、响应解析、前端气泡样式及文本截断逻辑，定位真实原因后再修改。

- AI 回复应语义完整、句子连贯，不允许出现半句话、丢失后半段或因 CSS 限制而隐藏正文的情况。
- 每轮最多 3 个气泡；较长的回答应优先精炼内容，再按完整句子拆分，不得直接删除超出字数限制的部分。
- 保留各实验阶段的必要信息，不得为了减少响应时间而删掉关键研究材料。
- 尽量缩短等待时间；提供明确的加载状态、合理的超时处理和失败重试机制。
- 不能通过反复追问、重复输出或无限延长回答来弥补模型理解问题。

### 4. 管理员可以查看完整对话记录

管理员后台增加或完善对话记录页面，能够查看：

- 参与者编号、实验路径、会话编号。
- 每条 AI 消息和用户消息的完整内容。
- 每条消息的时间戳、发送者身份和消息顺序。
- 观点确认事件、评分提交事件及实际评分。
- 会话开始、结束和异常中断情况。

记录应按参与者、会话和实验路径进行查询，时间顺序清晰。管理员可以查看完整记录，但普通参与者不能访问其他人的数据。

### 5. 永久保留已有测试编号及账号记录

我已经生成的测试编号必须保留，不得因本轮或后续代码迭代、服务重启、重新部署而消失。我会自行生成需要的测试账号。

- 不删除、清空或重建现有参与者记录和账号记录。
- 不在应用启动时重新初始化并覆盖数据库。
- 如需数据库迁移，优先采用兼容现有数据的增量迁移。
- 修改数据库前先确认可用的备份或恢复方案；无法保障现有数据安全时，停止破坏性操作并明确告知我。
- 重新部署后，验证原有测试账号仍可登录。

## 二、认知路径：严格执行既定实验状态机

认知路径的目标是围绕参与者最初提出的同一个负面刻板印象进行认知重评，而不是让 AI 围绕单一角度无限展开。

请保留既有状态机及研究材料，按以下顺序推进：

1. `stereotype_capture`：收集参与者对美国黑人的负面刻板印象及其来源。
2. `viewpoint_confirmation`：由 AI 中立复述具体观点，在聊天流中显示观点确认卡片，等待参与者明确确认。
3. `initial_rating`：显示初次观点信任度评分卡片，收集参与者本人填写的 0–100 分数。
4. `reframe_1`：社会结构因素。
5. `reframe_2`：媒体与算法机制。
6. `reframe_3`：反刻板事实。
7. `reframe_4`：个体差异与文化多样性。
8. `second_rating`：针对最初确认的同一个观点，显示二次评分卡片。
9. `action_intention`：询问参与者是否愿意减少观看、关注或传播相关负面刻板印象信息，并完成收尾。
10. `completed`：结束实验。

- 保留已有研究材料规定的轮次与阶段限制；采集观点及来源阶段按现有材料控制在 2–3 轮。
- 每个认知重构子阶段都必须有明确的任务目标，完成后进入下一阶段，不得在同一个角度持续追问。
- 不得跳过四个重构子阶段，不得提前进行二次评分，也不得在二次评分时更换最初确认的观点。
- 状态推进由服务端确定性控制，不允许模型自行决定实验阶段已经完成。
- 继续使用既有的 `STAGE_RESPONSE_SUBMITTED`、`VIEWPOINT_CONFIRMED` 和 `RATING_SUBMITTED` 等状态事件及相应校验逻辑；如当前实现存在缺失，应修复而不是绕过。
- 只有参与者实际确认观点、提交有效评分或完成相应阶段任务后，系统才能按规定推进状态。

## 三、观点确认卡片和评分卡片必须嵌入聊天流

目前确认区域长期固定显示在聊天界面中，并与普通消息输入区并存，导致参与者不知道应该在哪个位置操作。

- 观点确认卡片只在系统完成观点提取、需要参与者确认时出现。
- 初次评分卡片只在观点确认后出现。
- 二次评分卡片只在四个认知重构阶段全部完成后出现。
- 卡片必须像聊天消息一样嵌入对话历史，而不是固定悬浮在输入框上方。
- 每张卡片只允许执行当前阶段规定的操作。提交后，活动卡片应转为已完成的只读记录或摘要，并在需要时显示下一张卡片。
- 普通自由文本消息直接发送，不应被自动放入一个要求确认的独立小弹框。
- 观点确认卡片和评分卡片是研究流程中的必要交互，不得因统一聊天界面而取消。

## 四、验收与交付要求

请先检查现有代码，完成修改后运行相应测试，并提供以下结果：

6. 旧测试编号和账号在重新部署后的保留验证。
