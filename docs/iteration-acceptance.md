# 每轮内部验收与人工测试闭环

**第45轮更新**：内部Staging按[快速迭代规则](staging-fast-iteration.md)执行：首次真实PG18最低校验备份后，纯UI/独立Prompt且三个风险字段全false不要求每轮重新备份/完整恢复；风险变更需新备份。下文完整备份/隔离恢复门槛继续用于Production或风险评审，不能机械套到每次内部Staging。手动部署与每轮人工smoke仍保留。

每轮都执行；自动化检查、真实模型检查、人工内部测试和线上验收分别记录。此流程不授权部署。研究者明确批准之前保持 Render autoDeploy=false；不清库、不重建账号、不改 API Key。

## 先记录基线

记录完整 Git 提交、上一轮交付标签/ZIP 校验值、变更清单、迁移和环境变化；逐项说明研究材料、状态机、Validator、账号分组、数据库是否变化。不得覆盖前轮报告或失败日志。

## 自动化回归

运行完整 `npm run check`，保留原始日志、退出码、Vitest 文件/测试数和 Playwright 数量。认知、情感、日常每轮都跑；涉及的路径另加专项测试。不放宽断言。失败后先保留日志再修复并重跑完整检查。CI 在成功和失败时均保存日志与浏览器 JSON，保留14天；交付时另存到对应轮次目录，不把 CI 临时保留期当永久归档。

涉及 Prompt、模型适配器、气泡或长度规则变化时，针对所有受影响路径追加真实模型格式检查；记录脱敏输入、原始输出、实际模型、HTTP状态、耗时、尝试次数和违规。外部真实调用必须与 Mock 分开报告；格式 smoke 不代表完整路径或人工语义审核。未运行填 NOT RUN。

## 人工测试和数据安全

每轮随报告提供人可执行的清单：页面、账号类型、点击步骤、预期结果、截图位置和停止条件。无线上部署时，线上人工项全部保持 NOT RUN。研究者填写真实结果后才闭环；不能根据代码或自动截图代填通过。

部署之前逐一核实原服务数据库、work分支、当前Live提交及增量迁移兼容性；完整加密备份和隔离恢复验证必须覆盖账号哈希、分配、会话、消息、状态、变量、事件、评分及系统通知。记录私有备份位置/校验值和恢复证据；禁止上传备份、密钥、账号密码到 Git。研究JSON/CSV不替代数据库备份。不得通过新建收费资源绕过备份。

`npm run acceptance:gate -- <本轮证据JSON> <完整实现提交>` 是**只读证据完整性检查**：退出0代表所需部署前记录齐全，2代表仍阻塞，1代表文件/参数错误。它依赖真实且经审核的记录，不会连接 Render、验证备份真实性或自动部署；不得为了输出0填写假证据。研究者批准必须独立取得。每轮本地检查只支持继续本地测试，不自动放行线上、导师或正式实验。

机器记录应含 implementation_commit、automation（command/exit_code/vitest_tests/vitest_files/browser_tests/log/scope=local）、三条 paths、presentation_or_model_changed、必要的 real_model，以及 predeploy 的逐项验证、backup_sha256/backup_evidence。参考第41轮 delivery-status.json。即使部署记录齐全，online_accepted 仍要求匹配实际Live提交、ready、旧账号和人工测试证据；mentor_test_ready/formal_ready 不由这个有限闸门授予。

## 后续获批部署

备份及隔离恢复完成、审核通过、研究者明确批准后，才手动部署现有Free服务。Live后先检查/api/ready和实际提交，再验证部署前已存在的账号、分组、历史、评分及管理员导出，随后按本轮人工清单操作。失败立即停止扩大测试，保留脱敏证据并检查连接/迁移；不重置账号、不清库。004已有记录时不能down；旧round38不认识004，不能盲目回滚到旧应用。保留数据库，采用兼容004的前向修复或经验证兼容版本。
