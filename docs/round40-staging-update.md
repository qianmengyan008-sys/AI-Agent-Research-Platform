# 第40次内部测试站更新与恢复说明

当前状态：仅提交代码与本地验收，未部署。由研究者决定是否更新现有Render Free服务。无需新建服务、付款或重填API Key。

## 更新前

1. 在具备现有数据库权限的受控环境，取得完整Postgres备份（包括账号哈希、分配、会话、消息、变量、事件及系统消息）。仅下载研究JSON不等同可恢复账号的数据库备份。凭据和明文备份不能进入Git或普通日志。
2. 使用既有 scripts/encrypted-backup.mjs 加密封装，密钥与备份分开保管；记录校验值。在独立隔离目标恢复并核对约束、表计数和旧测试账号登录。切勿把恢复命令指向当前研究数据库。
3. 本轮实际演练只在本地临时Postgres完成，尚无Render/异地恢复成功证据。在现有线上备份和恢复能力未确认前，不应把这份本地报告当作线上保证。
4. 私下保存至少一组未完成旧账号的实验UUID、编号，以及当前消息/评分/分配基线；不把密码截图上传GitHub。

## 研究者决定部署之后

核对服务仍连接原托管数据库、work分支和Free方案，保留现有ADMIN_ACCESS_TOKEN与RESEARCH_BOOTSTRAP_SECRET。不要删除服务、数据库、环境变量或旧批次。选择现有服务Manual Deploy → Deploy latest commit。根render.yaml的autoDeploy仍为false。

001–003迁移文件原样保留；004只增chat_notice表及不可变约束。它不重建账号表，也不更新旧参与者和消息。正式更新前请看交付版本号及protected-scope.json。

部署Live后，先访问/api/ready，再用部署前的固定账号和研究者已创建账号重新登录，核对实验UUID、分组、消息全文、评分、顺序；刷新、退出登录和重新登录均不应生成新开场。此步骤本轮尚未执行，不得预先勾为通过。

新日常四组：后台选择来源实验，创建四组日常实验配置（复制该来源模型批次）；再在新实验编号管理按人物创建自己的测试账号，下载独立登录Excel。旧通用DAILY账号没有四组身份资料，不会随机补组。四组原头像仍缺失，目前仅为文字占位，不代表正式头像材料验收。

## 失败恢复

保留数据库，先检查日志并前向修复。004一旦已有记录，不执行down迁移，不删除记录来让回滚通过。旧round38只认识001–003，严格迁移历史校验会拒绝未知004；不能简单退回该旧应用并期望正常启动。需要回退时，应使用认识004的兼容代码（例如第39次实现）并再次验证，或做前向修复，不能清库。

只有隔离目标的恢复演练被允许作为本轮测试。任何线上恢复须先核对目标、备份及授权，不能覆盖当前研究库。既有已完成实验保留只读历史；没有批准的重开/每日分轮方案时，不自动回退状态。
