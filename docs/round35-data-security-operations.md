# 正式研究的数据管理与运维责任清单

本文件是待研究者批准的运行方案，不是伦理批准，也不代表正式业务已经开放。两年托管服务期限不自动等于个人数据或备份必须保存两年；数据保留期由研究目的、知情同意和适用要求决定。

## 数据与权限

正式数据只进入新的Production PostgreSQL，不保存在Web临时磁盘；B001/B002内部测试数据不复制到正式研究库。模型请求仍由服务端Adapter发出，不把API Key交给浏览器。向模型供应商发送哪些字段、是否需要脱敏和跨地区传输，应在正式知情同意和数据最小化清单中批准。

参与者仅能访问自己的会话；原系统隔离测试作为工程基础，正式入口、部署及正式账号必须重新验收。当前production-preparation入口不接受任何参与者或导出，不能把关闭接口的测试解释为正式业务权限已完备。

研究者应指定：研究负责人（批准材料/保留政策和放行）、受授权数据管理员（私密导出/访问审计）、运维责任人（升级、监控、备份/恢复、告警）、恢复审批人（受控获取密钥及临时恢复权限）。单一共享管理员Token不代表每位管理员都有独立身份审计；正式多人管理员身份、权限最小化和撤销机制应在启用前设计确认，当前不宣称已实现。

## 导出与审计

导出需管理员授权，完整导出必须complete=true，核对记录计数、数据质量、版本和生成时间。审计保留操作者身份、目的、时间、实验/范围、文件摘要和交付去向；普通运行日志不记录对话全文、口令、数据库连接或Secret。现有admin_event能力保留；正式预备入口不开放导出，正式服务的审计需部署后实测，不能只看字段存在。

导出文件存入研究机构受控私有位置，访问到期或撤销后移除。禁止GitHub公开链接、在聊天粘贴Secret、共享全体参与者账号表或将对象存储桶设公开。源数据与匿名分析副本分开管理，映射表只由必要人员访问。

## 退出、撤回、保留与删除

知情同意应说明参与者如何暂停/退出、是否可恢复、撤回申请受理方式、可删除的范围及已匿名分析数据的处理边界。当前实验规则和退出流程未因部署修改，不能承诺尚未实现的自动撤回/删除功能。

删除请求由研究负责人审核身份和适用范围，形成受控记录后由有权限人员实施；须同时考虑消息、状态、变量、模型运行/审计、导出副本、供应商侧规则和备份保留窗口。不要临时手改数据库或直接删除数据库容器；需可复核计划、备份处理策略与完整性验证。备份中的历史记录按获批生命周期和恢复后删除清单处理，不能仅清主库就声称全部副本删除。

## 日常/季度运维与事故

每日检查健康/HTTPS、数据库容量/连接、作业结果、独立备份成功心跳与账户余额/费用。重要版本上线前额外备份，记录Git/部署/配置版本并保留回退方案；不在活跃批次悄悄更换模型或研究材料。

至少每季度做一次异地恢复演练，核对全部记录、权限与完整导出；关键迁移前增加演练。正式运行需定义RPO/RTO和责任人，本轮没有声称提供24小时值守或恢复SLA。

发生泄露/异常写入/密钥疑似泄露时暂停招募和新增访问，保护脱敏证据，由责任人按机构流程评估影响、轮换受影响Secret、核验权限/导出记录并决定通知；不要把Secret粘到事故工单或公开日志。恢复必须先在新隔离目标验证，不覆盖现有库或删除失败证据。

正式放行前逐项签署：正式材料/知情同意、数据最小化、模型服务与地区、访问授权、数据与备份保留期、退出/撤回方案、运维和事故责任、真实恢复与容量验收。当前均不得由Codex代签。
