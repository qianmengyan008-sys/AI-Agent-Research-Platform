# 开发计划与验收

## 本轮交付

只交付架构、数据库逻辑模型、状态机、模块划分和开发计划。未创建应用、数据库迁移、测试框架或部署资源，未接入模型。设计检查不能代替未来运行测试。

## 阶段 1：无 AI 状态机与后台

先建立 Node.js/TypeScript 工作区、React 前端、Express 后端与独立 PostgreSQL 开发库；添加数据库迁移、环境变量样例、固定文本生成桩和测试基础设施。实现实验版本、账号与分配、状态服务、事件审计、会话恢复，以及最小管理员操作页面和参与者任务页面。

使用专用演示路径验证公共框架，不把演示数据当作正式研究刺激。接入标准安全哈希及会话机制，参与者编号不能单独作为登录凭据。启动前检测数据库连接和迁移版本，测试库与开发库隔离。

验收：全新测试数据库能执行迁移；管理员创建账号并分配；参与者登录后只看到本人会话；有效事件可推进，非法跳步不可推进；消息、变量和状态在重启后恢复；管理员可以查看并导出测试数据。以上均由自动化测试覆盖。

## 阶段 2：可替换模型服务

实现 generation 接口、配置化适配器、当前阶段上下文构建、超时/限次重试/失败回退、持久化生成租约和调用元数据。先用模拟供应商验证契约，再按需要接入一个真实供应商。密钥由独立环境配置注入，不写入仓库。

验收：替换适配器不修改状态机；Prompt 不含完整流程或未来阶段；模型输出无法推进状态或写入变量；供应商失败、重复回调、迟到回复及重启恢复有集成测试。真实调用为凭据和网络可用时的单独冒烟检查，CI 默认不调用外部模型。

## 阶段 3：三条实验路径

先冻结研究协议与量表，再分别实现认知、情感和日常路径定义、表单、阶段模板和变量 schema。每条路径沿用共同引擎，不复制独立编排逻辑。后台可配置草稿，发布不可变版本。

验收：三条路径端到端完成；认知前后评分分别存储；四阶段不跳步；情感七阶段顺序完整；日常条件无干预模板；条件固定且参与者之间数据隔离；导出可还原路径、变量、阶段与对话。

## 阶段 4：完整自动化回归与研究验证

自动化测试从阶段 1 开始，每次代码、数据库迁移或配置逻辑修改均运行对应测试；本阶段集中补齐回归、并发、恢复和导出验证，不能延迟到此阶段才测试。

| 层级 | 范围 | 执行时机 |
| --- | --- | --- |
| 单元（建议 Vitest） | 状态机、守卫、变量 schema、上下文构建 | 每次相关修改及 CI |
| API/数据库集成（Vitest + Supertest + 专用 PostgreSQL） | 权限、事务、幂等、迁移、并发、持久化与恢复 | 每次后端修改及 CI |
| 前端组件（Testing Library） | 当前阶段表单、错误与重试、服务端状态呈现 | 每次前端修改及 CI |
| 端到端（Playwright） | 管理员配置 → 参与者完成三条路径 → 查看导出 | 合并前及发布前 |
| 生成契约与语义评估 | 适配器失败、注入文本、阶段边界、日常非干预质量 | 适配器/模板修改后；真实模型评估单独记录 |

CI 门禁包含冻结锁文件安装、类型检查、必要构建及相关测试；禁止通过跳过失败测试完成验收。报告真实执行数量、失败/跳过和外部依赖限制。模型的语义表现需研究者评审，不能以静态或单元测试声称心理学干预有效。

## 阶段 5：独立实验部署

建立独立测试与研究运行环境、专用数据库及模型凭据；配置 TLS、会话保护、最小权限、访问日志、数据备份/恢复和版本化迁移。迁移与回滚方案按数据库变更审核；部署前验证备份恢复和人工停止实验。

验收：发布版本固定、数据可恢复、权限与导出通过回归、研究协议/同意/数据保留与模型数据处理要求明确、研究者完成试运行。正式部署需单独明确授权与目标资源；禁止使用 WorkBuddy 生产配置。

## 待研究者确定的参数

这些参数不阻止公共框架开发，但在正式路径发布前必须明确：

1. 认知重构四阶段的具体内容、负面刻板印象的采集范围、前后量表及行动意愿测量方式。
2. 情感路径人物设定来源、刺激材料、各阶段完成标准和最低互动要求。
3. 日常路径结束条件、聊天时长/回合数及是否收集结束反馈。
4. 条件是否手动分配或由后端预设随机化策略分配；第一版默认管理员手动分配并留审计。
5. 同意与退出要求、研究数据保留期限、模型可接收的数据范围和导出使用权限。

不确定内容以提案标注，不默认为正式实验参数。首次实现选择的开发端口、工具版本与具体依赖版本另在初始化时固定并提交锁文件。
