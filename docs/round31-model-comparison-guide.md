# GPT / DeepSeek模型对比操作说明

2026-10-14，仓库第31次交付，输入附件第29次反馈。只补对比诊断工具，不修改实验逻辑、Adapter、Prompt和冻结参数。当前GPT密钥和模型名未注入，真实对比尚未执行；已有DeepSeek Secret不代替GPT配置。

## 安全配置

在Codex云环境设置绑定 GPT_API_KEY，默认HTTPS目的地主机api.openai.com；设置 GPT_MODEL_NAME 为账户实际可用模型名。不要把密钥发到聊天或GitHub。兼容接口可通过GPT_API_BASE_URL换地址，但需要与真实服务主机匹配的Secret绑定，不把DeepSeek密钥共用给GPT。DeepSeek保持已有DEEPSEEK_API_KEY/DEEPSEEK_MODEL_NAME。

云环境草稿已增加GPT密钥要求和模型名字段，并保留原DeepSeek绑定/安装/网络设置。保存草稿不等于注入，需要用户填写、保存并发布，在运行环境核对存在后才能执行。模型名不猜测：有密钥不表示账户可用任意GPT名称或参数；选不支持temperature等共同参数的模型时须先处理兼容性，不能偷偷给两模型用不同参数。

共同参数：temperature=0.2、max_tokens=512、timeout_ms=10000、max_attempts=2。模型、端点可切换；每个已分配实验批次的配置固定，切换正式比较应创建新批次，不替换旧会话模型或重写状态。

## 两种对比范围

| 工具         | 输入与历史                                            | 能验证什么                                                       | 不能证明什么                                                   |
| ------------ | ----------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------- |
| 原32案例配对 | 每模型32个独立案例，初始完整Prompt相同，AB/BA交替     | 各阶段/异常表达的适配器与原Guard检查、时延、状态快照不被生成改变 | 使用demoPolicy，不能冒充冻结研究Prompt正式验收或连续对话       |
| 新25轮诊断   | 每模型认知/情感各25轮；当前阶段固定，使用mentorPolicy | 同阶段连续对话、非标准中文、指代/自然度/重复、自己的历史稳定性   | 不推进状态，非完整路径，不能证明API/DB、评分守卫或真实状态跳转 |

25轮认知固定REFRAME_MEDIA_ALGORITHM，情感固定RELATIONSHIP。这样不会延长正式情感实验的轮次上限，也不改导师冻结参数。两个模型共同的阶段/状态/当前输入/政策/参数相同，后续各自回复历史不同，完整Prompt自然可能不同；同时记录base和actual Prompt哈希。既不共享对方回复，也不声称所有轮次完整Prompt完全相同。

报告保留完整的25轮记录，但现有Context Manager只投影有限近期消息；模拟末轮实际投影6条，不能宣称模型能看见完整25轮历史。长对话的上下文裁剪、重复与指代质量需要对最终呈现及原候选一起人评。

## 命令与费用边界

以下是工程执行者命令，参与者无需安装软件；使用新输出位置，拒绝覆盖旧材料。

```sh
npm run compare:models -- /tmp/new-paired-comparison --fixture
node --import tsx scripts/model-long-dialogue-comparison.mjs /tmp/new-long-comparison --fixture
```

去掉--fixture才是请求真实模型，且必须先确保两模型的独立key/model均存在。真实命令使用Node代理支持；它们不会在安装、启动或普通check里自动执行。

```sh
npm run compare:models -- /tmp/new-real-paired
node --use-env-proxy --import tsx scripts/model-long-dialogue-comparison.mjs /tmp/new-real-long
```

用户本轮已选择“配置后执行小规模真实对比”。建议先32配对案例：64正常模型调用，最多128次HTTP尝试；审阅后再做连续诊断100正常调用/最多200次尝试。全部两部分预计164调用/最多328尝试，均为顺序小组诊断，不是30人并发。按每请求6000输入token、512输出估算，全套每家最多164次尝试即984000输入与83968输出；各家成本约0.984×各家百万输入价＋0.083968×百万输出价。输入是假定而非硬上限，未取得账户报价，不给虚构金额；需结合实际额度/计费核对。真实30人并发另行按round29预算获批准后做，不自动连带执行。

## 人工评价与结果解释

每轮原模型候选、最终呈现、Guard拒绝、兜底、时延和状态哈希都记录。流程错误率是原Validator标签的代理指标；状态违规是生成前后快照发生变化，两者分开。新连续工具的state_transitions为空，因为按设计不提交事件，不是“所有状态跳转都通过”。这也不验证模型复述的阶段是否语义正确，人评仍需查。

human-language-review-template.json提供六维1–5评分：中文清楚、逻辑、指代、不重复、实验一致性、非标准表达理解；实际人评后填评分/结论/问题等级/意见/审核人/时间。现有人工决定不覆盖，所有本轮评分null，平均值null；fixture表只是审核工具示例，不能当供应商自然度排名。真实样本应在新目录生成新评分表，不能给模拟表改“真实”标签。

当前真实延迟、错误率、状态违规次数和人工分数均未测。不要因为fixture中两个label为gpt/deepseek就把它们认作真实供应商数据。完成真实初步比较、稳定公网URL、本人完整流程体验、导出和无明显状态问题/语言审核后，才邀请老师。
