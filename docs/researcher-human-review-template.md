# 非脚本体验与人工语言审核记录

只填写研究者本人在实际部署入口完成的自由对话。不要把 QA001 脚本样例作为人工体验结果。认知、情感、日常各一轮，可以由同一研究者分别体验。审核同一次会话的完整导出，不另跑模型生成替代文本。

| 项目                                 | 研究者填写                 |

自然表达即可，不必按固定次序制造所有情况。适当记录出现过的：含糊表达、多观点、询问系统、评分时插话、短回复、离题、重新考虑。评分和观点确认必须由本人明确提交；其他阶段按批准的后端兜底处理。

## 每条回复的六维审核

| 维度                   | 通过的含义                               | 判定   |
| ---------------------- | ---------------------------------------- | ------ |
| 流程忠实度             | 确认观点、评分对象、阶段与人物／场景一致 | 待审核 |
| 回应性                 | 回应本次输入，没有忽略主要问题           | 待审核 |
| 自然性                 | 中文通顺，语气自然，没有明显机械拼接     | 待审核 |
| 语义准确性／指代清晰度 | 表述语义准确，人物、观点、对象指向明确   | 待审核 |
| 重复程度               | 不连续复述相同句式或无意义重复           | 待审核 |
| 中性表达               | 不默认赞同，不用“你说得很对”等诱导评价   | 待审核 |

各项结论只能填写“通过／需修改／无法判断”。保留原文、user_message_id、assistant_message_id、turn_id、阶段、reply_source 与异常依据。不根据代码测试或 HTTP 200 自动评分。字段齐全不代表语言质量通过。审核工具的待审核值应当由研究者逐条更新，保留原始导出和版本。

## 问题分级和处理

| 级别            | 例子                                                                             | 后续处理                               |
| --------------- | -------------------------------------------------------------------------------- | -------------------------------------- |
| A：实验忠实度   | 私自改变观点、评分对象不一致、阶段跳回、场景错位、人物身份错误、未完成任务就推进 | 必须修复；修复后重新完整体验受影响路径 |
| B：明显体验问题 | 大量重复、忽略输入、语病、机械兜底、结束后开新任务、等待明显过长                 | 主要问题需修复；重新验证对应路径       |
| C：可延期       | 轻微措辞、样式与外观                                                             | 登记，导师测试后处理                   |

问题登记：session_id／turn_id、原输入和原回复、六维判定、A/B/C、证据、建议、修复提交与复验结果。无法判断时写明缺少的上下文，不擅自写“通过”。
