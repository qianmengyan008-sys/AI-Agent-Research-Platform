# 两年期数据备份与恢复手册

本轮状态：加密工具和S3参考作业已准备；**本地真实PostgreSQL恢复PASS，自动异地备份/云上恢复NOT RUN**。没有存储账户、获批保留期或正式数据库，不把本地演练称为异地备份验收。

## 两层备份

第一层由付费托管数据库提供自动备份/PITR。恢复窗口、容量、连接限制、升级方式、备份计费和跨区域能力必须按实际账户确认。附件指出Render逻辑导出仅保留7天，本轮未再次在线核验，不能拿该导出代替两年备份。

第二层每日将PG17自定义格式逻辑备份加密后放到另一地区的私有对象存储。代码scripts/production-backup-job.mjs，密码从服务端环境传给pg_dump，不在命令参数或日志打印连接串；TLS强制verify-full，CA配置不正确就失败，不能关闭证书验证。备份凭据不得与管理员日常账号混用。

scripts/encrypted-backup.mjs使用版本头、随机nonce和AES-256-GCM认证加密。解密全部认证通过后才原子发布恢复文件，错误密钥或篡改不会留下可用明文；已有目标文件拒绝覆盖。数据库转储和临时明文只放在0700临时目录，作业结束清理；加密文件权限0600。恢复只在专门的受控运行器进行。

密钥需以BACKUP_KEY_ID关联版本，旧版本密钥按获批备份保留期安全保存。密钥和存储恢复权限分开管理；没有可用密钥的密文不可恢复，不能只备份密文而丢失密钥。

## 自动作业与私有存储预检

deploy/backup-retention-review.json给出每日UTC 18:00（北京时间次日02:00）调度提案，**并未安装定时任务**。月初成功运行会额外上传monthly副本；若当天任务失败，必须由维护人补跑月归档，不能假设自动补齐。建议30份每日备份，按月保留期由研究者/伦理要求确认；版本化桶必须另配旧版本保留/删除策略，不能无限保留非当前版本。

参考作业需要独立PG17客户端、Node24与AWS CLI v2运行器，现有Web镜像未包含这些命令。平台/预算批准后由Codex准备并验证独立作业镜像和调度，不要求研究者安装工具或写命令。不得将不具备依赖的Web镜像直接当备份作业部署。

作业要求显式BACKUP_RETENTION_APPROVED=true。通过S3管理API核对存储地区、四项Public Access Block、非公开Bucket Policy及版本化，再上传加密对象和不含数据内容的清单。SSE同时开启；加密清单包含内容校验和、key_id、日期和部署版本。任何必备配置缺失、上传失败或对象大小不一致都退出非0。

源数据库实际地区与桶配置地区需在账户控制台核实，代码里的地区字符串差异不能单独证明物理异地。当前实现面向支持相关S3管理API的存储；**OSS等兼容服务不能只改Endpoint就宣称可用**，若不支持上述管理API应保留失败，待适配与真实验证，不删掉私有性检查。对象生命周期、恢复用户读权限和费用需单独验收，作业不会自行给桶配置删改权限。

失败时发送通用告警事件，不发送错误堆栈、连接串、聊天内容或密钥；即使通知端点失败，作业仍以非0退出并标记未送达。通知成功/失败分支已用本地模拟HTTP测试。外部告警端点、定时器和“超过24小时无成功备份”的独立心跳监测均未部署，需由指定维护人负责；不能把代码存在解释为有实时告警值守。

## 最小权限与保留

写入身份仅允许对应production前缀上传、读取对象元信息及必要的桶安全状态；不允许公开ACL，不允许删除正式数据库，不授予不必要的桶策略修改权。恢复身份另行授权读取指定备份，密钥访问需研究者或指定管理员批准。后台清单与审计记录不含参与者正文。

知情同意/撤回后，删除范围必须覆盖主库、导出副本及备份保留窗口中的处理方案，不能直接承诺修改不可变历史备份。先获批数据管理政策，再设置生命周期；没有批准前作业保持关闭。

## 恢复操作：由维护人员/Codex实施

1. 选择已上传成功的清单与密文，确认来源、部署/研究版本和对象版本，核验SHA256、key_id及审批。不要把下载链接设为公开。
2. 创建全新的隔离临时数据库；先核对名称、无数据及与正式/体验库不同。禁止对现有正式库运行覆盖、drop或--clean。源库保留且只读观察。
3. 从受控Secret取得对应密钥，解密到权限受限的临时文件。必须认证成功后才可pg_restore；原始临时明文不得上传GitHub或日志。
4. 使用PG17 pg_restore --no-owner --no-acl --exit-on-error恢复到空目标库。比较全部表计数、外键/约束、消息/状态/变量/模型日志及版本；不只比较文件大小。
5. 在隔离恢复环境验证参与者重新登录和只读历史、跨账号隔离、管理员完整complete=true导出及data_quality。真实恢复时禁止意外模型调用，临时运行器不绑定正式模型Secret。
6. 记录备份年龄、下载/解密/恢复/校验时长、记录差异、权限及导出结果。没有所有证据不得切换生产连接。RPO/RTO目标须先与研究者确认，不能凭一次本地演练承诺SLA。
7. 审核后清理仅本次创建的临时明文/容器/数据库，保留脱敏报告。正式数据切换要单独批准和可回退计划。

至少每季度演练一次，重要迁移前额外备份。云上存储下载恢复必须在平台批准后真实执行，本轮NOT RUN。

## 本轮真实本地演练结果

使用一次性PostgreSQL17源库和全新本地恢复库，3个合成参与者、3条路径，保存6条消息、3个模型运行日志和4个实验变量。实际pg_dump后认证加密、解密再pg_restore，21张表记录数相同；消息/状态/变量/模型日志快照一致；complete=true且data_quality通过；恢复后登录、历史和权限隔离通过；篡改/错误密钥/覆盖已有文件被拒绝。模型是模拟响应，外部模型调用0。
